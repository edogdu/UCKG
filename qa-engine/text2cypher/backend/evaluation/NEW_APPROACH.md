# README: Dataset Validator Script Enhancements

## 1. Summary of Changes

This document outlines the recent enhancements to the `dataset_validator.py` script. The script has evolved from a simple validator into a comprehensive **Enrichment and Validation Pipeline**.

The new approach is designed to take a *raw* dataset (containing only `NaturalLanguageQuestion` and `CypherQuery` columns generated by an LLM) and automatically process it into a fully enriched, validated, and analysis-ready file.

The pipeline is now a clear, multi-step process:

1. **Gatekeeper Check:** Validates the raw data for duplicates and halts if any are found.  
2. **Enrichment:** Programmatically generates all other necessary columns from the Cypher query.  
3. **Save:** Saves the newly enriched dataset to a new file.  
4. **Validation:** Runs a full, five-stage validation suite on the enriched data to check for schema, executability, and semantic correctness.

---

## 2. The New Enrichment & Validation Pipeline

### Step 1: Initial Duplicate Check (Gatekeeper)
- **Function:** `check_for_initial_duplicates()`  
- **Output File:** `duplication_check.txt`  

**What it Does:**  
Before any processing, this function performs a strict check for duplicate `(Question, Cypher)` pairs in the raw input file.

**Why it's Important:**  
This is a critical gatekeeper. If duplicates are found, the script halts execution and logs the problematic entries. This prevents you from wasting time processing a flawed dataset and allows you to clean the raw LLM output first.

---

### Step 2: Data Enrichment
- **Function:** `enrich_dataset()`  

**What it Does:**  
Once the dataset is confirmed to be unique, this function parses every `CypherQuery` and automatically generates all the helper columns. This turns your raw file into a complete, analyzable dataset.

**Columns Generated:**
- `ExpectedNodeLabels`
- `ExpectedRelationshipTypes`
- `ExpectedProperties`
- `Hops`
- `ExtractedPropertyValues` — extracts all literal strings and numbers from the query (e.g., `"FIN7"`, `3`), used in the new validation stage.

---

### Step 3: Save Enriched Dataset
**What it Does:**  
The script saves the complete, in-memory dataset (which now includes all the newly generated columns) to a new file, typically named  
`neo4j_evaluation_dataset_ENRICHED.csv`.  
This new file is the final, processed output.

---

### Step 4: The Five-Stage Validation Suite
After enriching and saving, the script runs a full validation suite on the new, in-memory data.

#### Stage 1: Schema Adherence Check
- **Function:** `validate_schema_elements()`  
- **Output File:** `schema_check.txt`  

**What it Does:**  
Verifies that every node label (e.g., `:UcoCVE`), relationship (e.g., `-[:HAS_PROPERTY]->`), and property (e.g., `.label`) used in the query actually exists in the `schema_cache.txt` file.

---

#### Stage 2: Cypher Executability Check
- **Function:** `validate_query_executability()`  
- **Output File:** `cypher_check.txt`  

**What it Does:**  
Runs the Cypher query against the Neo4j database (with `LIMIT 1` appended) to ensure it executes without error.

---

#### Stage 3: Entity Extraction Check
- **Function:** `validate_expected_entities_match_query()`  
- **Output File:** `entity_check.txt`  

**What it Does:**  
This check now serves as a sanity check for the enrichment process. It confirms that the entities found in the query string perfectly match the data that was just auto-generated for the `Expected...` columns.

---

#### Stage 4: Semantic Relevance Check
- **Function:** `validate_semantic_relevance()`  
- **Output File:** `question_cypher_relevance.txt`  

**What it Does:**  
Uses a Sentence Transformer model (`all-MiniLM-L6-v2`) to calculate the cosine similarity between the `NaturalLanguageQuestion` and the `CypherQuery`.  
This ensures the query is semantically related to the question.

---

#### Stage 5: Value Consistency Check (NEW)
- **Function:** `validate_extracted_values_in_question()`  
- **Output File:** `value_check.txt`  

**What it Does:**  
This is a crucial new check to catch LLM value hallucinations. It compares the literal values extracted from the query (e.g., `"CVE-2025-41233"`) against the text of the question to ensure they match.

**Recent Improvements:**  
This check is now highly robust. It uses:
- An `IGNORE_LIST` to skip common, non-data values like `true`, `false`, `1`, or `0`.
- Flexible word matching (checking for word overlap) to correctly handle partial matches, such as finding `"SolarWinds"` in the question for the query value `"SolarWinds Orion Attack"`.

---

## 3. Structural and Logging Improvements

- **Dedicated Log Files:**  
  The script now creates six separate `.txt` files (including `duplication_check.txt` and the new `value_check.txt`), making it easy to isolate specific types of failures.

- **Robust Error Handling:**  
  The `close_loggers()` function was fixed to prevent an `AttributeError` if the script fails before the log files are created, ensuring a clean exit.
